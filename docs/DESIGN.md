# 算法、接口与边界

2026-11-18 更新：本文下述密集、流式、检查点及旧报文接口描述 0.1.0 兼容路径。新增标准路径使用完整 477 行参数表、`TransmissionInfo`、`StandardBlockEncoder`、`StandardBlockDecoder` 与 `EncodingPacket`；源块、子块交织和聚合包不再排除在项目范围之外。算法与标准覆盖见 [RFC 6330 整改矩阵](RFC6330-整改与符合性.md)。

## 编码路径

对象按 RFC 6330 的 Partition(Kt,Z) 划成连续源块。N=1、Al=1，每个块无需子块交织；只有对象尾部补零。每块从标准表选择最小 K'≥K，构建 S 行 LDPC、H 行 HDPC 和 K' 行编码约束。源符号填入 K 行 RHS，K～K'−1 是隐式零符号。

GF(256) 使用多项式 0x11d；加法为 XOR，乘法表由移位约减生成。测试用独立的多项式卷积和长除法核对全部 65,536 个乘积。Rand、Degree 和 Tuple 按标准常量和 UInt32 回绕产生确定性编码索引。修复符号的 ISI=ESI+(K'−K)，不能直接把 ESI 当作 ISI。

`Encoder::new` 用有界稠密消元求中间符号，随后按编码索引生成每个符号。`EncodingPlan` 求出相同 K 的线性变换，适合重复的小符号对象，但需要额外系数存储。实测表明大 T 时计划复用也可能慢于直接求解，接口没有承诺自动提速。

## 接收路径

批量解码先收包，再建立约束并求解。流式解码预先加入预编码和补零约束，收到一个符号后只对新行消元。找到新主元才提交方程；依赖且 RHS 非零的方程返回不一致错误。反代复制 RHS，不破坏接收状态，允许重复读取结果及继续检查额外方程。

批量接收恰好 K 个不同源符号时，直接按 ESI 排序并拼接，decode 无须建立消元系统；含修复符号或额外方程时仍执行正常求解与一致性检查。两类求解器的行运算对系数 0 跳过、系数 1 使用 XOR，其余系数复用循环外取得的乘法表行；单位主元不再归一化。最坏稠密消元复杂度不变，测量见 `reports/OPTIMIZATION.md`。

进度中的 independent 是扣除已知预编码与补零约束后的独立信息量。received 是保留的不同 ESI 数，两者可能不同。完整解码依赖秩达到 K，并不是凑够包数。

`ObjectDecoder` 为未完成的块按需建立流式解码器，达到满秩时恢复并释放密集矩阵。默认最多 4 个活跃块，可设 1～16；预算已满时拒绝新块，调用方可稍后重试。完成块只保留原始字节和进度，忽略其后到达的有效帧，**不继续检查迟到包是否与先前内容冲突**。

## 报文和输入验证

OTI 使用标准 12 字节布局，检查保留位、长度、T、Z、N 与 Al。支持单符号包，报文长度必须恰为 T+4；不接受聚合包、非本对象源块号或截断包。单块和多块的分帧器共用固定大小缓冲逻辑；每次 push 先处理临时状态，全部有效才提交，错误不会丢失同一次输入中此前解析出的包。

每块最多保留 K+64 个不同 ESI；相同 ESI、相同字节返回 false，不同字节返回冲突。过大的对象、符号或包预算在分配矩阵前拒绝。分帧器每实例最多 65,536 个帧，留存缓冲为 T+4 字节；返回数组仍会占用本次输出帧的内存。

FEC 不保证损坏检测。方程恰好满秩时，错误数据也可能解出另一个对象。不同对象若使用相同 OTI 和 ESI，格式层无法识别混用。对象身份、摘要、签名及可信 OTI 应由调用方提供。

## 检查点续传

单块检查点 v1 只保存可移植信息，不序列化消元矩阵或后端内存。布局为 `RQCP`、版本字节 1、保留字节 0、网络序 UInt16 包数、12 字节 OTI、按到达顺序排列的标准包、网络序 CRC32C。最小 24 字节，最多 1,312,024 字节；每块最多 K+64 个不同 ESI。

读取顺序为长度和版本检查、OTI 参数检查、包数与精确长度检查、CRC32C、逐包格式与重复检查。流式恢复随后重放符号并验证方程一致性；批量恢复在 decode 时验证一致性。重复 ESI 的检查点即使内容相同也拒绝，避免把收包历史误写成保留状态。完整包读取通过后才返回新接收器，失败不会改变原接收器。

检查点内的标准符号可以跨本库两个解码器和三个后端交换；外层 `RQCP` 属于本项目存储格式，独立 Rust 库不直接读取它。CRC32C 只能检测意外损坏，没有绑定对象身份，不能替代签名。多块对象目前不提供整个对象的统一检查点 API，可由调用方按块管理单块状态。

## 复杂度与范围

L=K'+S+H。稠密系数存储为 O(L²)，RHS 为 O(LT)，消元最坏时间为 O(L³+L²T)。流式路径减少重复建立方程的成本，并没有改变稠密消元的最坏复杂度。编码计划保留 O(LK) 系数。

`stream_storage()` 给出数字元素和保留 payload 的结构估算，不包含数组头、分配器、输入所有权、临时副本或 GC 预留，不能当成进程峰值 RSS。多块对象还需保存已恢复块；活跃矩阵数量受预算约束。

旧兼容路径限 K≤256、N=Al=1，最大 16 MiB 对象来自 16 块×256 符号×4096 字节。新增稀疏路径支持完整 K 参数范围与 OTI 字段，采用失活求解；资源不足时返回 ResourceLimit。SIMD、真实传输服务和安全更新协议未实现。完整 RFC 6330 符合性是最终目标，现有互操作样本仍不足以证明第 5.8 节的全表恢复性质。
