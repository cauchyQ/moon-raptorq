# RFC 6330 整改验证记录

日期：2026-11-18。验证环境为 Windows 11、MoonBit v0.10.19 / moon 0.1.20261102；独立参考为 WSL 内 Rust raptorq 2.0.0。新路径属于准备中的 0.2.0，Mooncakes 已发布的 0.1.0 不包含这些接口。

## 邮件问题与本次修改

邮件驳回原因是申报范围明确排除完整参数支持、未以完整标准符合性为最终目标。本次已同时修改申报范围与代码：参数表从 K′≤257 扩为全部 477 行；新增完整 OTI、子块交织、多符号包和稀疏失活路径。旧设计文档中的排除项已标明为历史版本边界。申报书没有把当前测试写成完整标准认证。

## 本地检查

Wasm、Wasm GC、JavaScript 三个后端均通过严格 check、release build 和全部 **117 个测试**，各运行六个示例。CLI 独立进程测试覆盖编解码、保存、续传、等待状态及非法参数；完整命令见 [local-checks.json](local-checks.json)。

新增测试包括：逐个检查 K=1..56403 的最小 K′ 选择；稀疏与密集约束比较；小块编码字节差分；K=257/511/1024 恢复；T=65535 的修复恢复；40 位对象长度及最大 OTI；预算拒绝、秩不足、不一致方程、源块路由、聚合包冲突回滚和整包范围校验。最大块系统符号齐全时直接恢复，额外方程不会绕过求解检查。

## 新增大块双向验证

原始数据：[standard-interop.json](standard-interop.json)。各点 T=1；源数据第 i 字节为 `(i*17+11)%256`。丢弃 ESI 为 10 的倍数的源符号，补入 `ceil(K/10)+16` 个修复符号。

| K | MoonBit 编码耗时 ms | MoonBit 解码耗时 ms | Rust→MoonBit | MoonBit→Rust |
| ---: | ---: | ---: | --- | --- |
| 257 | 28.439 | 14.699 | PASS | PASS |
| 1024 | 97.512 | 88.974 | PASS | PASS |
| 4096 | 785.905 | 647.585 | PASS | PASS |
| 56403 | 60874.412 | 60675.646 | PASS | PASS |

这些是单次实际运行时间，不是多轮中位数，也不是跨机器性能承诺。最大块约需一分钟编码和一分钟解码，仍有性能改进空间。脚本显式设置 33,554,432 项稀疏系数预算；默认 8,388,608 项预算会拒绝该最大块轨迹。预算是元素计数，不等于 RSS。

Rust 产生的全部修复字节先与 MoonBit 编码结果逐字节比较，再由 MoonBit 接收恢复；MoonBit 实际输出随后交给 Rust 接收并核对源数据。高 ESI=16,777,215 的本库输出也被记录，但这些高 ESI 字节尚未由独立参考核验。

## 非默认布局双向验证

原始数据：[layout-interop.json](layout-interop.json)。三组 `(F,T,Z,N,Al)` 分别为 `(53,12,2,3,2)`、`(101,20,3,7,4)`、`(1025,8,4,2,1)`，合计九个源块。包含非均匀源块、尾部补零、对齐及零宽子块。

独立 Python 先按 RFC 公式划分、交织，再交给 Rust 编码，生成 MoonBit 恢复向量。反方向实际运行 MoonBit 编码，将其输出交给 Rust 恢复，再在 Python 逆交织并核对原对象，两个方向均 PASS。参考绑定没有自定义 OTI 对象入口，因此这里准确表述为“独立布局加 Rust 单块编解码”，并非 Rust 完整对象接口互操作。

## 复现

```powershell
python tools/check.py
python tools/verify_standard.py
python tools/verify_layout.py
python tools/source_lines.py
```

独立参考包安装见 README。CI 每次 push 或 PR 都运行大块和布局互操作，并上传报告；耗时不参与固定值比较。生成常量及独立参考向量单独计数，不计入手写算法规模。

## 证据边界

本轮已消除“将完整参数支持排除在项目范围之外”的申报问题，并提供超出旧版上限的实际编解码证据。**尚不能据此声称完整 RFC 符合性已经验证**：第 5.8 节涵盖全表的随机 ESI 恢复性质，需要更多抽样、置信说明及求解正确性论证；大规模下各后端的性能和内存行为也需继续记录。范围、实现与证据的逐条对应见 [符合性矩阵](../docs/RFC6330-整改与符合性.md)。
